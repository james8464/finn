# Plumb physical iPhone run sheet

Use this on a connected iOS 27 iPhone before claiming a working camera-to-result experience. Record the device model, iOS build, Plumb commit/build, tester, date, and each result in [`squat-v1-results.md`](squat-v1-results.md). This smoke run checks the app path; it is **not** a substitute for the 30-set holdout or specialist review in [`squat-v1-protocol.md`](squat-v1-protocol.md). Use a consenting tester and bodyweight squats only. Anyone else who appears in a check must have agreed to it.

| Check | Action | Expected result to verify |
| --- | --- | --- |
| First launch | Install a development build, open it, then tap **Set up camera** | Camera permission appears only after the tap; the preview is upright and matches the visible person |
| Denied permission | Deny Camera, tap **Try again**, then allow Camera in Settings and return | No live-analysis state while denied; the next attempt opens the preview without reinstalling |
| Setup and orientation | Place the phone upright at hip height, a few steps away; turn sideways | Full body fits in the preview; no unexpected mirroring or rotated pose result |
| Live skeleton | While framing, raise one arm, then squat slowly | Bones sit on the limbs and follow them without visible lag; the knee label changes as you bend; orange dashes appear only on joints that are hidden or blurred |
| Other people | During a set, a second consenting person walks behind the tester, then in front of the phone for about one second, then stands still to one side in view | Their skeleton is grey; the tester's stays white and never jumps to them; the walk-through does not change the count; standing in front for more than 3 s gives the "Someone else was in view" retake |
| Phone orientation | Frame yourself with the phone in portrait, then turned sideways each way, with rotation lock off and on | Picture and skeleton stay upright and on the body in every case; the picture behaves like a mirror (your right hand rises on the right of the screen); a squat filmed with the phone sideways still counts |
| First measured set | Do about six unloaded squats, tap **Stop set** | Count and named rep evidence match what the tester saw; any cue is camera-supported and understandable |
| Short or incomplete set | Stop after fewer than four full reps, then try an incomplete final rep | No unsupported technique cue or invented complete rep; retake path remains clear |
| Weak evidence | Safely obstruct the hip/ankle or move out of frame; test front and three-quarter views separately | Record whether Plumb abstains or gives a measured result. A measured unsuitable view is a validation failure to log, even if the UI looks plausible |
| Interruption | Background the app during preview and during a set; interrupt camera use if practical | Capture ends cleanly; no stale frames or false active-analysis state on return |
| Second set | Start another set in the same session | Comparison uses only the two completed sets and states changed/no clear change without a form or safety score |
| Local history | Save a result, lock and unlock the iPhone, then open History and inspect every measured rep in the saved session; delete one session and then all local data | Saved history remains readable after unlock; a temporary access failure offers **Try again**, while only confirmed corruption offers **Recover history**; deleted summaries remain absent after relaunch |
| Offline and optional recap | Turn on Airplane Mode, complete a set and comparison; try **Reword comparison** if offered | Core analysis works locally; unavailable or invalid generation uses reviewed wording |
| Accessibility | Repeat setup/result with Large Text, VoiceOver, Dark Mode, and Reduce Motion | Start/Stop stays reachable; recording status, result, evidence, and dismissal read in useful order |
| Duration and thermal | Run one long set until the two-minute limit; note temperature and memory behavior | Capture stops within the limit and produces an honest result or retake; no crash or runaway memory |
| Other exercises | Pick Push-up, Static lunge, then Stiff-leg deadlift on the first screen; do about six reps of each from the side | The framing status names that exercise's joints; the rep count matches a hand count; a set of another exercise does not produce a confident wrong result. Rules are first drafts, see [`exercise-rules-v1.md`](exercise-rules-v1.md) |
| 3D camera angle | Launch with `-plumb-validation`; frame side-on, at about 45°, facing the camera, and back to the camera | Side-on reads under 30°, 45° between 30 and 75°, front and back 75° or more; a 45° set is counted with a turn tip; a set filmed from the front for several seconds is refused. Record each readout. If side-on sets are refused, switch the check off in Options |
| Exercise recognition | Only once a trained model is in the build: turn on Options → Recognize the exercise automatically, set the picker to a different exercise, and do a set | The result says which exercise was used; an unknown movement falls back to the picker. See [`tools/exercise-classifier`](../../tools/exercise-classifier/README.md) |

For latency, launch from Xcode with `-plumb-validation`, manually tap **Stop set**, and copy the on-screen **Stop to result** value for each scored set into the protocol sheet. The automatic two-minute stop has no comparable tap latency. Record exact failures and the camera position used; do not turn a successful simulator test into a physical-device pass.
